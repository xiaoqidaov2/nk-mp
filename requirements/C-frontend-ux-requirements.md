# 方向C：Web 前端需求（信息架构 / 页面 / 交互）

> 归属：Nike 门店库存/价格监控平台（多客户商业监听服务）
> 上游输入：`00-project-context.md`（统一上下文）；数据形态参考 `scan_0924_0808.json`、`all_stores.json`、`probe_state_3752.json`、`watch.txt`、`gtin_cache.json`、`state.json`
> 适用范围：本文件只定义**前端（信息架构 / 页面 / 交互 / 体验 / 前端非功能）需求**，不定义接口契约与后端实现（见方向A/B）。
> 优先级口径：**P0 = MVP 必须交付**；**P1 = 首版后补齐（重要）**；**P2 = 增强 / 可选**。

## 0. 文档定位与三条硬边界

前端设计必须与 `00-project-context.md` 的能力边界严格一致，**任何 UI 都不得暗示不可得的数据**：

| 边界 | 前端必须遵守的表现 |
|---|---|
| B1 单店全量商品清单**纯接口不可达**（2.5） | 「单店在售清单」必须标注为**本店已监控货号结果 + 满减专区预览池（10 件轮换）**，禁止出现「全店共 N 件」等全量口径文案；页面内固定说明气泡 |
| B2 尺码级结果来自**只读审核**，非实时秒级 | 每个数据单元必须携带并可见 `checkedAt`（数据时间）；禁止标注「实时库存」，统一用「最近探测」 |
| B3 空完成响应不可信、WAF 405/401/网络抖动需重试 | UI 必须存在**第三种状态「数据不完整/探测失败」**，与「无货」严格区分；失败门店不得渲染为灰格（无货） |

## 1. 用户与使用场景

### 1.1 角色定义（前端权限模型的基础）

| 角色 | 代号 | 归属 | 说明 |
|---|---|---|---|
| 服务方管理员 | `ops_admin` | 服务方 | 全部客户、全部任务、账号池、数据源、调度、配额分配 |
| 服务方运营 | `ops_operator` | 服务方 | 日常盯盘：建任务、看进度、处理失败、重扫、配提醒；不可改账号池/客户套餐 |
| 客户管理员 | `tenant_admin` | 客户 | 本客户范围内的任务/门店/货号/提醒设置/配额查看；可增删本客户监控 |
| 客户查看者 | `tenant_viewer` | 客户 | 只读：大盘、矩阵、流水；可导出；不能改任务与通知设置 |

### 1.2 设备与场景矩阵（桌面为主、移动只读）

| 场景 | 设备 | 频次 | 允许的操作 |
|---|---|---|---|
| 建/改监控任务、全国扫描、看大矩阵、导出 | 桌面 Chrome/Edge（≥1440px） | 每天多次 | 全部（按角色） |
| 盯任务进度、处理失败重扫 | 桌面 | 每天多次 | 全部（按角色） |
| 看大盘 / 看某货号某店有没有码 | 手机（微信内置浏览器、钉钉内置、iOS Safari） | 每天多次 | **只看 + 收提醒**；P1 允许「单货号快速加监控」 |
| 收提醒（钉钉/企微卡片） | 手机 | 随时 | 只读 + 深链跳转 |
| 创建全国扫描 / 批量粘贴 / 导出 / 改规则 | 桌面 only | — | 移动端**不提供**（防止误操作烧配额） |

### 1.3 服务方运营每天盯什么（按时间线）

1. **开盘（09:00-10:00）**：大盘三块 —— ①昨夜至今变化量（★补货/✗售罄/¥变价/＋上新/满减专区变动）②任务健康度（失败与待重扫）③账号健康度与数据源灯。
2. **处理失败**：任务详情里看失败门店清单（401 冷却 / 405 挑战 / 网络 EOF / 空响应 / 无 GTIN 结构），点「仅重扫失败店」。
3. **接需求**：客户提「某货号全国有没有我的码」→ 批量粘贴货号 → 全国扫描 → 看命中矩阵 → 一键转成定时监控任务。
4. **盯配额**：今日审核请求数与剩余额度（100 店 × 单货号 ≈ 100+ 次审核请求），避免被限流。
5. **异常介入（唯一可能需要人工的环节）**：refresh_token 失效需一次浏览器静默授权 → 管理后台高亮待办 + 操作指引。

### 1.4 客户每天看什么

1. **收提醒**：钉钉/企微卡片（"DN3707-202 在南昌明矾 41/42/43 补货，实付 ¥1399"）→ 点链接直达矩阵并高亮单元格。
2. **早上扫一眼大盘**：今天我的货号里补了什么、卖光了什么、降了多少价。
3. **查特定货号**：某货号在哪些店有我的码、实付多少、有没有促销。
4. **看变化流水**：这周我关心的款发生了什么；导出 CSV 给同事。
5. **几乎不做**：改监控规则（首版由服务方代配，降低支持成本）。

### 1.5 关键用户故事（前端验收锚点）

- `US-C-01`（运营/P0）作为运营，我要**批量粘贴 20 个货号**发起全国扫描，并在 5-10 分钟内看到"哪几家店有货 + 各自有哪些码"，这样我不用逐店手查。
- `US-C-02`（运营/P0）作为运营，我要在扫描跑到一半网络抖动后**从断点继续**并**只重扫失败门店**，不重复消耗前 80 家已完成的结果。
- `US-C-03`（客户/P0）作为客户，我要在一张表里看到**货号 × 门店 × 尺码**的"有/无/价格/促销"，一眼分辨"灰的=没有"。
- `US-C-04`（客户/P0）作为客户，我要在**钉钉**收到补货/售罄/变价提醒，并点开直达对应门店与尺码。
- `US-C-05`（客户/P0）作为客户，我要确认我看到的数据是**什么时候探测的**，避免拿过期数据下单。
- `US-C-06`（运营/P0）作为运营，我要一眼看出**今天的失败门店与账号限流**，并知道平台是否在自愈。
- `US-C-07`（客户/P1）作为客户，我要**导出**这次扫描结果为 CSV/Excel 直接贴进自己的表。
- `US-C-08`（运营/P1）作为运营，我要看到**某货号实付价的历史曲线**，判断促销节奏。
- `US-C-09`（客户/P1）作为客户，我要在手机上打开链接**只读查看**矩阵（转成"门店列表"卡片流）。
- `US-C-10`（ops_admin/P0）作为管理员，我要看到**账号池健康**与**数据源状态**，在需要人工授权时被明确告知。

## 3. 页面需求（逐页）

> 每页给出：目标 / 核心区块与字段 / 主要交互 / 空态·加载·错误态 / 优先级。

### 3.1 概览大盘 `/dashboard` —— 今日变化 + 健康度

**优先级：P0**

**目标**：3 秒内回答"今天变了什么、系统是否健康、有没有需要我动手的"。

**区块与字段**

- `A. 今日变化（自今日 00:00 或上次登录以来）`：5 张并列统计卡
  - `补货 ★`：条数（= 尺码级"由无货→有货"事件数）+ 涉及货号数；hover/点击 → `/changes?type=restock&from=今日`
  - `售罄 ✗`：条数 + 涉及货号数
  - `变价 ¥`：条数；显示典型幅度（如"平均 -18%，最大 -¥314.55"）
  - `上新 ＋`：在线新品墙新增货号数（当前口径：`product_wall` 480 件 diff）
  - `门店活动`：满减专区规则变更店数 + 预览池进出件数
  - 每卡右下角统一小字：`数据截至 HH:mm`（取该类型事件最新时间）
- `B. 近 7/30 天变化趋势`：堆叠柱（补货/售罄/变价三色）+ 可切换指标；空数据日显示为 0 而非断点。
- `C. 任务健康度`：任务总数 / 启用中 / 最近一轮成功 / 失败 / **待重扫门店数** / 运行中任务数；一行"下一个任务预计 HH:mm 执行"；异常时置顶告警条（如"3 个任务上一轮失败，建议重扫" + 按钮进任务详情）。字段：任务名、类型、门店数、最近运行时间、耗时、结果摘要（命中店数/失败店数）、状态色。
- `D. 账号健康度`（ops_* 展示账号维度；客户仅展示自身"配额/延迟"聚合）：当前账号、**JWT 剩余有效期倒计时**、近 1h 401/405 次数、refresh_token 轮换状态、限流冷却标记、**是否需要人工介入（唯一红色高亮）** + 指引链接到 `/admin/accounts`。
- `E. 数据源状态灯`（ops_*）：`o2o cart_reviews` / `api-test product_details`(GTIN 结构) / `store/home`(满减专区) / `discover product_wall`(上新) / `product_details_availability`(在线尺码) 五项：可用性、近 1h 成功率、P50 延迟、最近错误摘要（WAF 405 比例、TLS EOF 比例、401）。
- `F. 待办`（P1）：配额已用 80%/95% 预警、客户套餐到期、待绑渠道的客户、连续 N 轮失败任务。

**主要交互**：卡片下钻（带筛选参数跳流水/任务）；区块可折叠（记住偏好）；右上时间范围切换（今日 / 7 天 / 30 天）；手动刷新（带"数据截至"实时更新）；`ops_*` 可按客户筛选（多选下拉）。

**空态 / 加载 / 错误态**
- 空态（无任务）：大字引导"还没有监控任务 → 新建监控任务 / 粘贴货号先查一次"，并给出 `DN3707-202` 示例按钮。
- 加载：统计卡骨架屏；图表骨架为浅灰基线；不做全屏 spinner。
- 部分错误：某数据源不可用时，**只把那块卡置灰并标注"数据源异常（405 挑战率 12%），影响上新，其余正常"**，不整页报错。

### 3.2 监控任务列表 `/tasks`

**优先级：P0**

**目标**：管理"监控什么、扫哪些店、多久跑一次、提醒给谁"的全部任务。

**区块与字段**
- 顶部：新建任务（主按钮）、批量操作条（选中后出现）、筛选区（可折叠，常驻记忆）。
- 表格列（默认）：`☑ | 任务名 | 类型 | 货号数 | 门店范围 | 尺码范围 | 频率 | 提醒规则摘要 | 状态 | 最近运行 | 下次运行 | 最近结果 | 客户(ops_*) | 操作`
  - `类型`：`单店精查` / `全国扫描（一次性）` / `定时轮询` / `上新监控` / `门店活动监控`
  - `门店范围`：显示摘要如 `全国 100 家` / `自选 12 家（粤浙）`
  - `尺码范围`：`全部码` / `41,42,42.5,43`
  - `提醒规则摘要`：`钉钉 · 补货+售罄 · 变价≥¥50 · 静默 24h`
  - `最近结果`：`7/100 家有货 · 3 家失败`（可点进运行详情）
  - `状态`：启用 / 暂停 / 草稿 / 已过期（一次性任务跑完）
- 行内快捷操作：立即执行（一次性任务显示"重新扫描"）、暂停/启用、复制为新任务、编辑、查看结果、删除。

**主要交互**
- 筛选：关键字（任务名/货号）、客户、类型、状态、门店（省/市/concept `NVS|NSO`）、尺码、创建人、更新时间区间。
- 排序：最近运行、命中店数、名称；支持列显示/顺序/宽度自定义并持久化。
- 批量：启用、暂停、删除、复制、导出任务配置（JSON/CSV）、批量加货号到所选任务（P1）。
- 「立即执行」必须弹二次确认，显示**预计消耗**（"约 100+ 次审核请求，预计 4-8 分钟"），防止误烧配额。

**空态 / 加载 / 错误态**
- 空态：无任务 → 引导卡片 + "导入示例任务（DN3707-202 全国扫描）"按钮。
- 加载：表格骨架 8 行；筛选切换时保留旧数据 + 顶部细进度条（避免闪烁）。
- 错误：加载失败 → 保留筛选条件 + 「重试」；权限不足 → 明确"该功能仅服务方可用"而非 403 白屏。

### 3.3 创建/编辑任务向导 `/tasks/new`（4 步）

**优先级：P0**（这是服务方的核心生产工具）

**目标**：把"货号 + 尺码 + 门店 + 提醒规则"在 60 秒内配好，并把配额成本透明化。

**步骤与字段**

- `Step 1 · 货号`
  - 输入方式二选一：单个输入框（自动补全历史货号）+ **批量粘贴大文本框**（右侧可展开）
  - 批量解析规则（必须实现并可见）：按**换行 / 逗号 / 空格 / 分号**分隔；自动 `trim`、转大写、**去重**、忽略 `#` 注释行（兼容现有 `watch.txt` 直接粘贴）；校验格式 `^[A-Z]{2}\d{4}-\d{3}$`（鞋服/配件通用 `XX0000-000`）
  - 解析结果三组反馈：`✅ 已识别 18 个` / `⚠ 重复 2 个（已自动去重）` / `❌ 疑似无效 1 行（第 7 行 "DN3707 202"）`，无效行可原地编辑或"仍然继续"
  - 支持从文件导入（.txt/.csv，P1）
- `Step 2 · 尺码范围`
  - 选项：`全部尺码（推荐）` / `指定尺码`（多选码段 chips：35.5–47.5 鞋码 / S–3XL 服装码 / 可手输自定义如 `41,42.5`）
  - **必须显示提示**："实际尺码清单在执行时按**门店各自的 GTIN 结构**解析（同款在不同门店可能结构不同），因此尺码列以结果为准。"
- `Step 3 · 门店范围`
  - 三种模式：`全国（100 家）` / `按地区`（省/市多选，来源为门店清单归一名；见 3.5 数据质量说明）/ `自选门店`（搜索 + 多选，列表显示 `店号 门店名 省市 concept`）
  - 支持"排除门店"；显示 `已选 12 家（含 NVS 10 / NSO 2）`；提供常用集合（珠三角/长三角/北京）快捷保存（P1）
  - 门店清单含**店号去重提示**：同名同店号不同 `regionId` 的重复项（如 3875 出现两次）默认按店号去重并提示
- `Step 4 · 频率与提醒规则`
  - 频率：`仅一次（全国扫描）` / `每 1h` / `每 2h` / `每 6h` / `每天 N 点（多选）`；**下一轮时间预览**（"首次 09:30，之后每 2h"）
  - 触发条件（多选）：`补货` / `售罄` / `变价（阈值：≥¥X 或 ≥Y%）` / `进入满减专区` / `上新命中监控货号`
  - 渠道：钉钉 / 企微 / 短信（依该客户已绑定渠道，未绑定则引导去 `/notifications/channels`）
  - 聚合与静默：`立即` / `5 分钟聚合` / `每小时汇总` / `每日 09:00 早报`；静默期 `同一货号+门店+尺码 X 小时内不重复`（默认 24h）；免打扰时段（默认 22:00–08:00 不推短信、可推汇总）
  - 接收人（钉钉 @手机号 / 企微 @成员，P1）
- `右侧常驻摘要栏（关键交互）`：实时显示 `货号 N × 门店 M × 平均尺码 K ≈ 单元格 N×M×K`、`本轮预计审核请求 ≈ R 次`、`预计耗时 ≈ T 分钟`、`占今日配额 ≈ P%`（超 80% 变黄、超 100% 阻断并提示改期或缩范围）。
- 底部动作：`保存为草稿` / `保存并启用` / `保存并立即执行`（后者需在确认弹窗再次显示预计消耗）。

**空态 / 加载 / 错误态**
- Step 3 若门店清单未加载成功 → 明确"门店清单获取失败，可先选'全国'（执行时重新拉取）"，不阻塞流程。
- 预计耗时/请求数后端未就绪时 → 显示"预估不可用"，**不得编造数字**（禁止假进度/假 ETA）。
- 校验失败 → 就地红字定位到具体行/字段，禁止整页 toast 掩盖。

### 3.4 任务详情 / 全国扫描进度 `/tasks/:id` 与 `/tasks/:id/runs/:runId`

**优先级：P0**（US-C-01 / US-C-02 的主战场）

**目标**：把 `--scan` 的"逐店扫描"过程与结果变成可看、可续、可重扫、可导出的界面。

**区块与字段**
- `运行摘要条`：`已扫 62/100 家 · 命中 5 家 · 失败 3 家 · 跳过（无 GTIN 结构）1 家 · 已用时 05:12 · 预计剩余 ~03:20`；`数据截至`；可信度徽标。
- `进度条`：分段着色（成功/命中/失败/跳过），**当前正在扫的门店名**滚动显示；支持 `中止`（中止后保留已完成结果并落为"可续跑"状态）。
- `实时命中列表（增量出现）`：`★ 南昌明矾换季优惠店（3910） DN3707-202 → 40,40.5,41,42,42.5,43,44,44.5,45`；每条右侧"加入监控""复制"。
- `结果矩阵（Tab）`：行=门店（仅显示有货 + 可选显示全部），列=尺码（按各店结构取并集）；单元格三态见 4.5；行尾列：命中码数、实付价、促销名。
- `失败与跳过清单（Tab）`：门店、原因分类（`账号 401/冷却` / `WAF 405 挑战` / `网络 TLS EOF` / `空完成响应（不可信）` / `无 GTIN 结构`）、重试次数、最近尝试时间；**顶部按钮「仅重扫失败店」**与「从断点续扫」。
- `运行历史（Tab）`：历次运行的时间、耗时、命中变化（如 `7→5 家`）、配额消耗、失败数；可对比两次运行（P1，见 3.7 历史）。
- `设置（Tab）`：任务配置只读视图 + 编辑入口。

**主要交互（对齐 `--scan` 语义，必须逐条实现）**
1. **断点续扫**：中止/失败后，「继续扫描（从第 63 家开始）」并明确文案："前 62 家沿用 12:04 的结果，不重复请求"。等价 `--skip` 的已完成前缀跳过语义。
2. **只重扫失败店**：`--skip` 的补集（仅失败集合）；重扫完成后**合并**到同一 run 结果，若同一门店前后结果冲突，以最新为准并在单元格标注"重扫更新"。
3. **逐店 GTIN 结构**：UI 明确"每店各自解析结构"，因此在扫描过程中某货号在部分店"无结构"是**正常**现象，显示为 `该店无此货号结构（跳过）`，不得算作"无货"。
4. **价格来源**：矩阵里的价格来自"全可买（≤3 件/批）"的审核结果，因此**部分有货门店可能没有价格**（Phase B 未取到）→ 单元格显示 `有货 · 价格待补`，并提供"补取价格"按钮（P1）。
5. **失败不得伪装**：任何失败/不可信门店在矩阵中显示为灰斜纹 `未探测`，与"灰=无货"视觉**必须区分**。

**空态 / 加载 / 错误态**
- 运行中：进度条 + 日志流（可展开"逐店日志"，含 `[62/100] 店名: ...` 级别信息，供运营排障）。
- 无命中：`已完成 100/100 家，全部无货`（如 `IF1823-010` 的 0 家）——**必须同时显示失败店数**，若失败 > 0 则主文案改为 `已完成 97/100 家，已探测门店均无货（3 家未完成）`。
- 实时连接断开：顶部黄条"实时通道已断开，正在重连…（显示为 20 秒前数据）"，回落为轮询；不得静默停更。
- 账号限流：明确"账号冷却中，将在 HH:mm 自动继续（已自愈 2 次）"，禁止显示为"已完成"。

### 3.5 单店视图 `/stores/:storeCode`

**优先级：P0**（客户高频："这家店有没有我的码"）

**目标**：一家店的完整画像 = 门店信息 + 满减专区预览池 + 该店已监控货号的尺码级结果。

**区块与字段**
- `门店信息卡`：`displayName`、`storeCode`、`regionId`、`省/市（归一字段）`、`concept`（NVS/NSO/SHANGHAI_001，显示为中文"换季优惠店/品牌体验店/上海001"）、`storeAddress`（可复制、一键复制用于导航）、`shippingTip`（"实付满¥600免运费"）、`activityFinished`（活动已结束标记）、"最近探测"时间。
- `满减专区预览池卡`：规则文案（`title` + `subtitle`，如"满减专区 / 鞋、服、配件 55折/7折；鞋、配件 6折"）、预览商品 **10 件**（图片 + 货号，图片来自 `store/home` 的 `colorwayImages`）、本期待变化（`[预览+入] / [预览-出]`）；每件商品行有"探测此货号"（加入单店探针）与"加入监控"。
  - **必须标注**："本专区商品为门店活动预览池（每期轮换 10 件），非全店库存清单。"（B1）
- `该店探针结果清单（主表）`：货号、标题、`有货 9/25 码`、有货尺码 chips（可点）、标价、促销额、实付价、促销名、最近探测时间、操作（加监控 / 看矩阵）。
  - 表头固定说明："**本清单仅包含我们已监控的货号**，不代表本店全部在售商品（该口径接口不可得）。"
- `门店维度变化（Tab）`：该店的 ★/✗/¥ 事件时间线 + 活动/预览池变更。

**主要交互**：复制地址；一键"探测预览池全部 10 件"（强烈建议 P0，这是目前最接近"店里有什么货"的可得替代）；按有货码数/实付价排序；切换到 `/styles/:code?store=…` 定位矩阵行。

**空态 / 加载 / 错误态**
- 该店无任何监控货号：空态引导"为该店添加监控货号"或"探测本店满减专区预览池"。
- 门店号不存在：友好提示 + 模糊匹配建议（如输入 `375` 提示 `3752 / 3754 / 3755 / 3758`）。
- 门店清单里的重复项（同店号两 `regionId`）：页面顶部提示"该店号存在 2 条记录，已按店号合并展示"。
- 地址无法归一出省市（实测 4 家地址无省市前缀，如 3458/3857/3876/3907 的原始地址）→ 省市列显示 `未知`，并提示"地址格式不规范，建议以店号为准"。

### 3.6 货号详情 / 货号 × 门店 × 尺码矩阵 `/styles/:styleCode`

**优先级：P0**（产品的心脏页，US-C-03）

**目标**：一张表回答"这个货号在哪些店有货、有哪些码、多少钱、有没有促销、什么时候变的"。

**区块与字段**
- `头部信息区`：货号（大字，可复制）、标题（来自各店 `gtin_cache` 的 `title`，多店不一致时取众数并标注）、`有货门店 7/100`、`全网最低实付 ¥1399`、`尺码跨度（并集）40–47.5 共 14 码`、可信度徽标、`数据截至`。
- `筛选与视图条`：`仅显示有货门店（默认开）` / `仅显示有货尺码` / `尺码区间` / `价格区间` / `仅看促销` / `仅看与上次变化` / `门店搜索` / `省·市` / `concept` / `视图：矩阵 | 列表`。
- `矩阵表（核心）`
  - 行 = 门店（100 家全集；默认"仅有货"过滤后 7 行）；列 = 尺码并集（鞋 ~25 码 / 服装 6 码，上限约 30 列）
  - 行字段：`门店名 | 店号 | 省市 | concept | 尺码1..K | 有货码数 | 标价 | 促销额 | 实付价 | 促销名 | 最近探测`
  - 单元格：有货（蓝底 + 码数可点）/ 无货（浅灰）/ **该店不卖**（斜纹灰 + `不售`）/ 未探测或不可信（斜纹 + `?`）
  - 冻结：首列（门店）与表头（尺码）冻结；列宽可拖拽；尺码列可按数字/字母排序。
- `历史变化（Tab）`：时间线（按时间倒序）：`★ 补货 41,42（09-24 07:20）` / `✗ 售罄 43` / `¥ 变价 实付 ¥1399→¥384.45（促销：指定鞋/服/配件 55折）`；可按门店/尺码/类型筛选。
- `价格曲线（Tab，P1）`：该货号各店实付价时间序列（默认取"变化最频繁的 5 家店"对比，可自选 ≤5 条线）；纵轴 ¥，横轴时间；**必须标注采样口径**："仅记录探测时间点与变化点，非连续价格"。
- `关联任务（Tab，P1）`：哪些任务/客户在监控该货号，可一键把本货号加入任一任务。
- 顶部主按钮：**一键加监控**（选择已有任务 or 新建"单货号全国扫描/定时轮询"，跳转向导并预填）。

**主要交互（见 4.2 详述）**：行列筛选、排序、单元格 hover 显示价格明细（标价/促销额/实付/促销名/`checkedAt`）、单元格点击弹出详情抽屉、复制整表为 TSV（可直接粘进 Excel）、导出 CSV/XLSX。

**空态 / 加载 / 错误态**
- **全网无货**（如 `IF1823-010` 实测 0/100）：主文案 + 副文案区分口径 —— "已探测 100/100 家，均无货"；若失败 > 0 则"已探测 97/100 家，已探测门店均无货（3 家未完成，结果可能不完整）"+ 重扫按钮。
- 从未探测过该货号：空态 + "立即全国扫描（约 4-8 分钟，消耗约 100+ 次审核请求）"按钮 + 预估消耗。
- 加载：矩阵骨架（保留行/列标题）+ 单元格渐进填充；大矩阵（100×30）不得整页 spinner。
- 部分数据不可信：表头黄条"12 家门店为不可信结果（空响应），已从'无货'统计中剔除"。

### 3.7 变化流水 / 通知历史 `/changes`

- `流水表格`（默认表格，非卡片）：`时间（相对+绝对） | 类型 | 客户 | 任务 | 货号 | 标题 | 门店 | 尺码 | 旧值 → 新值 | 促销名 | 探测时间 | 通知状态 | 操作`
  - 事件示例：`09-24 07:20 | ★补货 | 客户A | 全国扫描-3码 | DN3707-202 | Air Jordan 3 Retro 男子运动鞋 | 广州西环(3754) | 41,42,42.5,43,44 | — | — | 已通知(钉钉)`
  - 变价行显示 `¥1399 → ¥384.45（-¥314.55 / -22.5%，指定鞋/服/配件 55折）`
- `汇总条`：`本页 50 条：补货 12 / 售罄 8 / 变价 6 / 其他 24`；右侧"导出 CSV / 导出 Excel"。
- `通知历史（Tab）`：`发送时间 | 渠道（钉钉/企微/短信） | 接收方 | 触发任务 | 内容摘要 | 状态（成功/失败/重试中） | 失败原因（Webhook 404/加签失败/被限流） | 操作（重发）`；内容摘要可展开显示**实际发送的卡片预览**（Markdown 渲染，与渠道一致）。

**主要交互**：列排序；分页（默认 50/页）与无限滚动切换；行点击 → 定位到矩阵单元格（`/styles/:code?store=&size=&at=`）；多选后"标记已读""批量导出"；导出≥1 万行时走**异步导出中心**（生成任务 → 完成后通知，避免页面卡死）。

**空态 / 加载 / 错误态**：空态分两种文案 —— "还没有任何变化（首次采集后开始记录）" vs "当前筛选无结果（清除筛选）"；加载保留旧表 + 细进度条；导出失败给出明确原因（"行数超限，请缩小时间范围或改用异步导出"）。

### 3.8 通知设置 `/notifications`

**优先级：P0**（渠道绑定 + 基础规则）/ P1（高级规则、接收人）

**目标**：让客户在**钉钉/企微**里收到"能看懂、能点开、不刷屏"的提醒。

**渠道绑定（Tab 1）**
- 渠道卡（每渠道一张）：`钉钉自定义机器人`（Webhook URL + 加签 secret + 关键词/自定义关键词校验）、`企业微信群机器人`（Webhook URL）、`短信`（手机号 + 模板状态 + 资费提示，P2）
- 每卡字段：状态（已启用/已禁用/异常）、最近发送时间、最近失败原因、失败次数、"测试发送"按钮、编辑/停用/删除。
- **必须实现**：保存后自动发送一条测试消息并回显结果（成功/失败原因原文，如 `310000: sign not match`），避免客户以为配好了其实没通。

**规则设置（Tab 2）**
- 作用域：`全局默认` + 每个任务可覆盖（继承指示清晰：`继承全局` / `自定义`）。
- 触发条件：补货 / 售罄 / 变价（阈值 ≥¥X 或 ≥Y%）/ 命中上新 / 进入满减专区。
- 聚合策略：`立即` / `5 分钟聚合` / `每小时汇总` / `每日 09:00 早报`（默认建议：补货=立即、变价=每小时汇总、售罄=立即）。
- **静默期**：同一 `货号+门店+尺码` X 小时内不重复（默认 24h，可 0/1/6/12/24/168h）。
- 免打扰：时段 + 该时段仅推送汇总。
- 渠道级限速：每渠道每分钟 ≤ N 条（超过则自动合并为一条汇总，防刷屏/防被平台判定骚扰）。
- `消息模板预览（必需）`：右侧实时渲染**钉钉 Markdown 卡片**与**企微 Markdown** 实际样式，示例内容：
  ```
  【补货提醒】DN3707-202 Air Jordan 3 Retro 男子运动鞋
  门店：NIKE广州西环换季优惠店（3754）
  补货尺码：41 / 42 / 42.5 / 43 / 44
  价格：¥1399（无促销）
  探测时间：2026-09-24 08:10 · 数据完整（100/100 家）
  [查看矩阵] →
  ```
  - 卡片必须包含：`货号 + 标题 + 门店 + 尺码 + 价格 + 探测时间 + 可信度 + 深链`；**小屏可读性要求**：正文 ≤8 行，长尺码列表折叠为 `41-44 共 5 码`。

**空态 / 加载 / 错误态**：未绑定任何渠道时，任务向导第 4 步顶部提示"未绑定渠道，提醒将只记录不发"；渠道配置错误时在通知历史里能看到原始错误并一键重发。

### 3.9 配额与账户 `/account`

**优先级：P0**（用量视图）/ P1（趋势与预警）

**目标**：让服务方与客户都清楚"用了多少、还剩多少、被限流没有"。

**区块与字段**
- `用量三卡`：`监控条目数`（= Σ 任务 × 货号 × 门店，例：3 货号 × 100 店 = 300 条）、`今日审核请求数`（近似 = Σ ceil(尺码数/40) + Σ ceil(有货码/3)）、`剩余额度`（含进度环 + 重置时间 `明日 00:00` 或套餐周期）。
- `速率与冷却状态`：当前 QPS 使用率、最近 1h 401/405 次数、是否处于冷却、下次自动重试时间（**必须展示自愈过程**，让客户知道平台没挂）。
- `按任务/按客户分布表`（ops_* 看全客户；客户看自身）：请求数、命中数、失败数、平均耗时、单次成本近似。
- `近 14 天请求量趋势`（柱/线，含失败堆叠）。
- `预警设置`（P1）：阈值 80%/95% 通知渠道与接收人。

**交互**：时间范围切换（今日/7 天/本月/自定义）；点击某任务下钻到任务详情运行历史。

**空态 / 加载 / 错误态**：无任何任务 → 卡片显示 0 并引导创建；额度耗尽 → 顶部红条"配额已用尽，新扫描将被拒绝（可联系服务方扩容）"，同时禁用向导里的"立即执行"。

### 3.10 服务方管理后台 `/admin`（仅 `ops_*`）

**优先级：P1**（客户管理与账号池为 P0/P1 边界，建议账号池健康先上）

#### 3.10.1 客户管理 `/admin/tenants`
- 列表：客户名、联系人（姓名/手机/钉钉）、套餐与配额、已绑渠道、任务数、监控条目数、本月请求数、创建时间、到期日、状态（启用/停用）。
- 详情抽屉/子页：基本信息、渠道绑定、任务清单、用量、**代客户配置入口**（跳转到客户上下文）、停用/启用客户（停用后其任务暂停并说明原因）。
- 交互：新建客户（含初始化渠道与默认规则，减少支持成本）、搜索/筛选、导出客户清单。

#### 3.10.2 账号池健康 `/admin/accounts`
- 每账号：`账号标识（脱敏） | JWT 剩余有效期（倒计时） | refresh_token 状态（正常/即将轮换/已失效） | 近 1h 401/405 次数 | 冷却状态 | 健康分（0-100） | 最近使用任务 | 操作（切换/暂停/标记待授权）`。
- **待人工介入视图（唯一人工环节）**：refresh_token 失效账号单独置顶，附**逐步操作指引**（浏览器静默授权一次）+ 需要谁做（ops_admin）+ 影响范围提示（"该账号下 12 个任务将暂停"）。
- 账号健康总览：可用账号数、冷却中、待授权、今日轮换次数。

#### 3.10.3 任务调度监控 `/admin/scheduler`
- 队列视图：`运行中 / 排队 / 近期失败 / 已熔断`；每项显示任务、客户、进度、耗时、当前门店、重试次数。
- 表格：任务、客户、上次运行/耗时、结果（命中/失败/跳过）、失败原因分类统计、下次计划、操作（立即执行/暂停/重扫失败店）。
- 系统级：并发度使用、平均单店耗时（P50/P95）、过去 24h 运行成功率趋势。
- 熔断/退避可视化：某任务连续失败 N 轮后自动退避，需明确显示"已退避，下次 HH:mm"。

#### 3.10.4 数据源状态 `/admin/sources`
- 五个来源各一行：`名称 | 用途 | 认证要求 | 近 1h 请求数 | 成功率 | P50/P95 延迟 | 405 挑战率 | 401 率 | 网络错误率 | 最近错误样本 | 状态灯`。

  - `product_details_availability`（在线渠道尺码，匿名）

#### 3.10.5 操作审计 `/admin/audit`（P2）

## 4. 关键交互模式

### 4.1 全国扫描闭环（创建 → 进度 → 结果矩阵 → 转监控）

```
① 入口            ② 配置            ③ 确认消耗                ④ 进度             ⑤ 结果                ⑥ 转监控
批量粘贴货号  ──▶  尺码/门店/频率  ──▶ 约 100+ 次审核请求 ──▶  [i/N] 逐店进度  ──▶  命中矩阵 + 失败清单  ──▶ 一键加监控
（含解析反馈）      （全国 100 家）    约 4-8 分钟/货号         实时增量命中        可续扫/只重扫失败        （定时轮询）
                                    占今日配额 P%（>80% 黄）   可中止             可导出 CSV/Excel
```

**必须实现的行为清单**
- `[P0]` 批量粘贴解析反馈（识别/去重/无效三态），兼容 `watch.txt` 的"每行一个货号"格式。
- `[P0]` 进度必须**按门店粒度**可见：`[62/100] 门店名`、成功/命中/失败/跳过四类计数、ETA。
- `[P0]` **断点续扫**：中止或崩溃后可"从前 N 家之后继续"，并明确"前 N 家沿用 {时间} 的结果"。
- `[P0]` **仅重扫失败店**：失败集合独立重扫并合并结果，冲突以最新为准。
- `[P0]` **失败原因分类**：401/冷却、405 挑战、网络 EOF、空完成响应（不可信）、无 GTIN 结构 —— 分类可筛选、可复制（便于报障）。
- `[P0]` 完成后结果可直接导出（结构对应现有 `scan_MMDD_HHMM.json`：门店 → 货号 → 尺码列表）与导出 CSV。
- `[P0]` 从扫描结果一键"加入监控"（转为定时轮询任务，预填货号与门店）。
- `[P0]` 空结果二义性消除：`全部无货` 与 `部分失败未完成` 文案必须不同。
- `[P1]` 扫描期间可离页：进度在后台继续，顶栏显示全局进度胶囊（"扫描中 62/100"）。
- `[P1]` 运行历史对比：本次 vs 上次命中的增减（新命中/失去命中）。
- `[P2]` 保存为"扫描模板"复用（货号组 + 门店集合）。

### 4.2 「货号 × 门店 × 尺码」矩阵的筛选与排序

| 交互 | 行为 | 优先级 |
|---|---|---|
| 仅显示有货门店 | 默认开启；关闭后展示全部 100 家（含无货灰行） | P0 |
| 仅显示有货尺码 | 隐藏全店皆无的尺码列，压缩列数 | P0 |

| 价格区间 | 按实付价筛（`≤¥500`），无价格行归入"价格未知"桶 | P1 |
| 仅看促销 | 只显示 `discount > 0` 的门店行 | P0 |
| 仅看变化 | 与上次快照 diff，只显示 ★/✗/¥ 涉及的门店与尺码 | P0 |
| 门店搜索 | 名称/店号/省市/地址模糊匹配 | P0 |
| 排序 | 有货码数 ↓（默认）、实付价 ↑/↓、门店名、省市、最近变化时间 ↓ | P0 |
| 列宽/列序持久化 | 按用户 + 页面记忆（localStorage 或账户偏好） | P1 |
| 单元格 hover | 弹出明细：标价/促销额/实付/促销名/`checkedAt`/该尺码是否在售但无货 | P0 |
| 单元格点击 | 右侧抽屉：该店该货号完整尺码表 + 该单元格历史变化 | P1 |
| 复制为 TSV | 一键复制当前视图（含表头），可直接粘贴进 Excel | P1 |
| 全量/大数据模式切换 | 小结果集（≤1000 行）用标准表格（**保证 Ctrl+F 可用**）；大结果集用虚拟滚动 | P0 |

### 4.3 批量操作

- `[P0]` 表格多选（含 `Shift` 范围选、`全选当前筛选结果`）、批量启用/暂停/删除/导出。
- `[P0]` 批量粘贴货号（换行/逗号/空格/分号分隔、`#` 注释、去重、无效行定位）。
- `[P0]` 批量门店选择（按省/市、按 concept、关键字搜索、一键全选/反选、排除）。
- `[P1]` 批量加货号到已有任务；批量改提醒规则；批量改频率（改频率需显示配额影响）。
- `[P1]` 批量删除必须显示影响预览（"将删除 3 个任务、12 个客户可见的监控，今日已消耗请求不退"）。

### 4.4 提醒 → 深链定位（闭环）

- 卡片链接 → `/styles/:code?store=:storeCode&size=:size&highlight=1&at=:ts`。
- 落地行为：仅显示该门店行（或置顶），**目标单元格描边高亮 + 轻微闪烁一次**，顶部黄条提示"你点开的提醒：2026-09-24 08:10 的探测结果（当前数据已刷新，最新 12:04）"。
- 若该数据已过期/已变化 → 明确提示"该码已售罄/价格已变（现价 ¥X）"，**不得静默显示旧态**。
- 未登录/无权限 → 登录后**回到原深链**（不用跳到首页）。
- 移动端落地：门店卡片流中对应卡片置顶并高亮。

### 4.5 数据状态语义与视觉（防误判，最重要的一致性规则）

| 状态 | 数据来源 | 文案 | 视觉 |
|---|---|---|---|
| 有货 | 未被 `error.errors[]` 列出（排除法） | `有货` | 蓝底/蓝点，码数可点 |
| 在售但该码无货 | `INVENTORY_INSUFFICIENT` | `无货` | 浅灰底（"灰的都是没有的"） |
| 该店不卖 | `PRODUCT_NOT_BUYABLE` | `不售` | 斜纹灰 + `不售` 角标 |
| 未探测 / 探测失败 | 网络/401/405/空完成响应 | `未探测` | 斜纹灰 + `?`（**与无货不同**） |
| 有货但价格未取到 | Phase B 未完成（≤3 件批次未成功） | `有货 · 价格待补` | 蓝底 + `¥?` 角标 |
| 结构缺失（该店无此货号） | `product_details` 无 `products` | `该店无此货号` | 极浅灰 + 说明 tooltip |

- 图例常驻表格右上；`不可信` 数据默认**不参与**"全网无货/有货店数"等汇总结论，汇总旁标注"（已剔除 N 家不可信）"。

## 5. 视觉与体验要求

### 5.1 品牌与克制（不臆造）
- **不使用 Nike 官方 Logo、Nike 字体（Futura/Nike Font）、Nike 品牌色作为平台自身视觉**；商品图片与标题按数据原样展示（来源 `store/home` 的 `colorwayImages`、`gtin_cache.title`），并在页脚声明数据来源与"非官方，仅信息聚合"。
- 平台自身为**中性商务后台风**：主色 1 个 + 语义色（成功/警告/危险/中性灰）4 个，避免大面积品牌色与渐变；无插画、无 3D。
- 不出现"Nike 官方""实时库存""全店库存"等易被误解的表述。

### 5.2 中文业务后台习惯（硬性）
- **信息密度优先**：表格行高 36-40px，字号 13-14px，一屏尽可能多看行；卡片区与表格区比例克制（先表格后图表）。
- **表格优先**：首屏即数据表，筛选器可折叠但带已选条件计数（`筛选(3)`）；列头支持固定/拖拽/自定义。
- **Ctrl+F 可用**：标准模式表格必须使用**真实 DOM 文本**（不用 canvas 渲染文字），保证浏览器查找能命中货号/门店名；结果集大时提供"大数据模式（虚拟滚动）"开关并提示 Ctrl+F 受限。
- **一键复制/导出**：每个表格右上固定 `复制为 TSV` + `导出 CSV` + `导出 Excel`；CSV 必须带 UTF-8 BOM（Excel 中文不乱码）。
- **键盘**：`/` 聚焦搜索、`j/k` 行移动（P1）、`Enter` 打开详情、`Esc` 关抽屉、`Shift+点击` 范围多选。
- **时间**：统一 `Asia/Shanghai`；相对时间（`3 分钟前`）+ hover 绝对时间（`2026-09-24 08:10:44`）；所有数据携带并可见"数据截至"。
- **文案**：全中文（含错误、空态、按钮、tooltip）；术语统一：`货号（style code）`、`门店`、`尺码`、`补货/售罄/变价/上新`、`探测`、`满减专区`。

### 5.3 移动端（只看 + 收提醒）
- 只做只读查看与提醒落地；**不提供**批量粘贴、全国扫描创建、导出、规则编辑（避免误操作与配额风险）。
- 单列卡片流；表格全部退化为卡片；触控目标 ≥44px；首屏 <2s（3G/4G 下首屏内容可见）。
- 卡片链接必须可分享（复制链接），且深链在钉钉/企微内置浏览器可直接打开。

### 5.4 可用性与无障碍
- **不单靠颜色**：状态同时用符号/底纹/文字（`★/✗/¥`、斜纹、`不售`、`未探测`），色盲可辨。
- 对比度 ≥4.5:1；焦点态可见；所有图例有文字说明。
- 危险操作二次确认（删除任务、删除客户、停用账号、批量删除）。
- 全局错误不吞：任何请求失败都有可见反馈 + 重试入口 + 可复制的错误详情（脱敏，不含 token/JWT）。

## 6. 前端技术需求（非实现细节）

### 6.1 实时 / 轮询
- `[P0]` 任务进度需**准实时**（用户感知 <3s 更新）：优先 `SSE`/`WebSocket`，回退为 **2-3s 轮询**；轮询必须支持"断线重连 + 指数退避 + 标签页隐藏时降频/暂停（`visibilitychange`）+ 恢复时补齐"。
- `[P0]` 进度必须可见"最后更新时间 + 连接状态"（已连接/重连中/已断开，显示数据龄）。
- `[P0]` 服务端未提供预估时，UI 显示"预估不可用"，**绝不伪造 ETA**。
- `[P1]` 顶栏全局进度胶囊（跨页面持续可见）。

### 6.2 大表格性能（100 店 × ~30 码 ≈ 3000 单元格）
- `[P0]` 目标：数据返回后**首屏渲染 <1.5s**；滚动稳定 60fps；hover/筛选不触发全表重渲染（按需更新单元格/行）。
- `[P0]` 技术策略（择一或组合，由实现决定）：行列虚拟化、canvas 渲染（仅在"大数据模式"）、行/列级 memo、事件委托、冻结表头与首列。
- `[P0]` `Ctrl+F` 在标准模式下必须可用（真实文本 DOM）→ 提供"标准模式 / 大数据模式"切换并说明取舍。
- `[P1]` 排序/筛选在**前端**完成（数据已全量持有）时，操作响应 <300ms；超大数据集走服务端筛选并显示 loading 行内态。
- `[P1]` 导出不阻塞 UI：>5000 行走服务端异步导出（进度 + 完成后下载/通知）。

### 6.3 图表
- `[P1]` 价格曲线：多店对比（≤5 条线）、可 hover 显示 `¥实付 + 促销名 + 探测时间`；**必须标注"仅变化点/探测点采样，非连续行情"**。
- `[P1]` 库存码数时间线（某店某货号的有货码数变化，步进线）。
- `[P1]` 请求量/失败率趋势（大盘与管理后台）；失败与成功堆叠。
- `[P0]` 所有图表在无数据时显示"暂无足够数据（需 ≥2 个探测点）"，不得画空坐标轴误导。
- `[P2]` 图表导出 PNG；数据下钻到流水。

### 6.4 权限与可见性（前端职责）
- `[P0]` 前端按角色隐藏入口/操作，但所有权限判断**以服务端为准**（前端不做安全边界）。
- `[P0]` 客户上下文切换（`ops_*`）必须**显式可见当前处于哪个客户视角**（顶栏色条 + 客户名），防止误操作到其他客户数据。
- `[P0]` 客户侧不得出现：账号池、其他客户、内部 `regionId` 列表以外的内部标识、请求成本明细中的账号维度。
- `[P0]` 无权限操作返回 403 时，给出"该操作仅服务方可用，可联系服务方"的友好提示，而非白屏/原始错误。

### 6.5 兼容性、时区与其他
- 浏览器：桌面 Chrome/Edge 最近两个大版本；移动 iOS Safari 15+、Android Chrome、微信/钉钉内置浏览器。
- 时区固定 `Asia/Shanghai`；不做多语言（仅 `zh-CN`），但文案集中管理便于后续。
- 前端**不直接调用 Nike 接口、不存储任何 token/JWT**（只调用自有后端）。
- 弱网策略：表格/矩阵数据本地缓存（`stale-while-revalidate`），离线时明确标注"离线数据（{时间}）"；不允许离线时展示为最新。
- 埋点（P2）：任务创建成功率、扫描平均耗时、导出使用率、深链打开率，用于产品迭代。

## 附录 B：已知数据质量项（前端需容错或提示）

1. **门店重复**：`all_stores.json` 100 条中 99 个唯一店号 —— `3875` 出现两次（`id: xian` 与 `id: NIKE0S08`，同名同址）。前端须按店号去重或明确提示。
2. **地址无省市前缀**：实测 4 家（3458 淮海潮流体验店、3857 福州福银、3876 杭州江滨、3907 贵阳机场）地址无标准省市前缀 → 省/市筛选依赖后端归一，缺失时归入"未知"。
3. **逐店 GTIN 结构不同**：同一货号在不同门店尺码集合可能不同（实测两套 GTIN）→ 矩阵尺码列取并集，单店仅按其自有结构判定。
4. **价格仅在全可买且 ≤3 件/批时返回** → "有货但无价格"是正常状态，不能显示为"价格 0"。
5. **空完成响应不可信** → 显示为"未探测/不可信"，不得计入"无货"。
6. **概念类型**：`NVS` 92 / `NSO` 7 / `SHANGHAI_001` 1 → 前端需给出中文显示名与筛选。

## 附录 C：明确不做（避免越界与误导）
